# NBA Salary Efficiency Analyzer
#### Video Demo: https://youtu.be/-Red-H6I2mc
#### Description:

For my final project, I decided to create what I call the NBA Salary Efficiency Analyzer. This idea was inspired by my interest in sports analytics and my love for sports in general. As a sports management student, I have always been interested in statistics and how they can be used to evaluate teams and players to make better decisions. The purpose of the NBA Salary Efficiency analyzer is to compare NBA players based on their value on the court relative to their salaries. I feel that just looking at how many points scored by a player does not accurately represent their overall value on the court. Because of this I created a production metric that includes points, rebounds, and assists to get a better idea of their true value. This metric is then compared to each player's salary to see which players are giving the most production compared to how much they earn. This is helpful because teams want players that produce at a high level relative to their salaries rather than players who earn large contracts without providing solid production.

The program begins by getting player data from a CSV file which contains each player's name, team, salary, minutes played, points, rebounds, and assists. In order for python to read the player data, I used the csv.DictReader to store each individual player as a dictionary, with all of the dictionaries stored in a list. I also converted the numerical data from strings into integers so that it could be used in calculations later on. After all of the data is loaded, I created several functions that calculate production and salary efficiency. These would later be used to give the user options such as ranking players, searching players, comparing players, and filtering the players based on how many minutes they played. By breaking my code into smaller functions it made it easier to organize and test.

I designed this program to be simple and easy for users to navigate though the interactive menu. The first option allows users to view the top players based on what their salary efficiency score is. The higher the salary efficiency score, the higher the rank of the player. Before the rankings are dislayed, the user can choose how many players they want displayed in the rankings. The second option allows for users to search for any player by name and recieve all of that player's stats such as salary, points, rebounds, assists, minutes, production score, and efficiency score. The third option allows for users to compare two players and see which one is more salary efficient. This is deteremined based on who has a better efficiency score. Finally, the fourth option allows users to change the minimum minutes requirement to filter players in the rankings. I added this feature because it can prevent players who played with a smaller sample of minutes to appear near the top of the rankings simply because they hapened to perform well in that small sample of minutes.

One of the biggest designs I made in the project was creating my own formula for player production rather than using an already existing statistic. I thought that using just a player's points wouldn't fully show a player's production on the court, as there are so many other aspects of the game. I instead created a weighted formula that used points, rebounds, and assists. Rebounds had a weight of 1.2 and assists had a weight of 1.5 because I felt that they had more value compared to just points. After calculating the production score I then divided it by the player's salary in millions of dollars to create my salary efficiency score. I also divided up my program into several smaller functions that each had a very specific task such as calculating production, calculating efficiency, loading data, ranking players, filtering players, searching players, or comparing two players. This made the program easy to organize and debug. To make sure my program was working properly I created a test_project.py file using pytest to test the calculation and search functions.

Overall, I feel that this project gave me the opportunity to apply what I learned, as well as doing something that I am passionate about. While creating this program, I got a lot more comfortable with dictionaries, lists, csv, and testing my code. One of the biggest challenges I faced was learning how to organize this larger problem into smaller functions to make it easier to debug later on. In the future I plan to work on this project to make it even better by adding more statistics and allowing for more flexability with players. I am proud of what the final product of this project looks like and it showed me how python can help to solve real world problems.
